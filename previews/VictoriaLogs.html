Why VictoriaLogs?

  • Start querying without defining a schema. Ingest structured and unstructured logs; VictoriaLogs creates the indexes needed for querying. Data model.
  • Go from a message to an aggregate. Search text, filter fields, and build statistics with LogsQL.
  • Keep your collection pipeline. Send logs with supported collectors and protocols, including OpenTelemetry. Ingestion options.
  • Choose a deployment that fits. Run a single binary or a cluster with separate ingestion, query, and storage roles. Both are open source. Cluster architecture.

Try it locally

With Docker installed, start VictoriaLogs:

docker run --rm --name victorialogs \
  -p 127.0.0.1:9428:9428 \
  -v victorialogs-data:/victoria-logs-data \
  victoriametrics/victoria-logs:v1.53.0 \
  -storageDataPath=/victoria-logs-data

In another terminal, send two example log messages:

printf '%s\n' \
  '{"_msg":"checkout completed","level":"info","service":"checkout"}' \
  '{"_msg":"payment timed out","level":"error","service":"checkout"}' |
curl -X POST -H 'Content-Type: application/stream+json' \
  --data-binary @- 'http://localhost:9428/insert/jsonline?_stream_fields=service'

Open VMUI and run level:error. You should see the payment timeout message. Logs without timestamps receive the ingestion time. Data persists in the named Docker volume. Full quick start.

How it works

Run the ingestion, storage, and query functions in one binary, or scale them separately as vlinsert, vlstorage, and vlselect. Architecture details.
