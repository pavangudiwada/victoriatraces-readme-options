Why VictoriaTraces?

  • Use your OpenTelemetry instrumentation. Ingest spans over OTLP/HTTP or a separately enabled OTLP/gRPC listener. Ingestion guide.
  • Find a request, then investigate it. Use the built-in Trace Explorer and waterfall, or query span data with LogsQL. Querying.
  • Keep familiar query tools. Connect Grafana's Jaeger data source or Jaeger UI through the supported Jaeger query APIs. Supported APIs.
  • Run without a separate storage service. Store traces on disk with a single binary or an open-source cluster. Storage · Cluster.

Try it locally

With Docker installed, start a single-node instance:

docker run --rm --name victoriatraces \
  -p 127.0.0.1:10428:10428 \
  -v victoriatraces-data:/victoria-traces-data \
  victoriametrics/victoria-traces:v0.12.1 \
  -storageDataPath=/victoria-traces-data

For an existing OpenTelemetry-instrumented application running on your host, set:

export OTEL_EXPORTER_OTLP_TRACES_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_TRACES_ENDPOINT=http://localhost:10428/insert/opentelemetry/v1/traces

Restart the application with these settings and send it a request. Open Trace Explorer; allow for the default search delay. Applications in containers need a reachable host address instead of their own localhost.

No instrumented application yet? Follow the sample-span and demo instructions. Data persists in the named Docker volume.

Find the request you need

Filter by service, operation, duration, or span attributes. Select a result to preview its services and duration, then open the full trace. Explore the query interface.

How it works

VictoriaTraces uses the VictoriaLogs storage engine internally; you do not need a separate VictoriaLogs instance. In cluster mode, vtinsert, vtstorage, and vtselect separate ingestion, storage, and querying. Architecture details.
